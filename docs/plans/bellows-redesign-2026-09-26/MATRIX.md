# Responsive and accessibility matrix (issue 287)

Generated by `e2e/matrix.spec.ts` at commit `f93bb8b5f40e5be1ffaa43c381bb5d1f9b31aae3`. A cell reads `pass` when the page
is no wider than the viewport (`scrollWidth <= innerWidth`, and the body does not overflow) and
every control outside a named scroll region sits inside it; otherwise the overflow in px.

The commit above is the base; the run measured the issue-287 working tree on top of it (the fixes
listed under "What the matrix found"). Chromium headless, offline seeded boards, 2026-09-28.

## What the matrix found, and what changed

The first run against `main` failed three things; each is fixed in the same change:

- **account/default at 320 (both themes): +35px page-level overflow.** The signed-in account's
  worktree path is one unbroken `code` run; the `.kv` grid's value column took its min-content
  width. `.kv dd` now breaks with `overflow-wrap: anywhere`.
- **Compact targets under 44px at 768 and 390.** Sortable `table.data` headers and row buttons
  (dashboard tables, workflows), the env editor's Add variable / Edit as .env and its raw-form
  field, select and buttons (organization, workspace, workflows), the account's create-token row
  (now `.token-create`), and five disclosure summaries (the chart's "How this is calculated",
  the task Outcome head, "View raw output", gate rows, onboarding's repository scope) joined the
  shared 44px rule. The summaries keep their native marker (`display: list-item`) and the gate
  rows stay full-width flex rows.
- The rest (names, live regions, keyboard reach and rings, forced colors, reduced motion,
  rendered contrast, dialogs) passed on the first run. A negative-control test plants one defect
  per detector (overflow, off-screen control, unnamed control, polled count in a live region,
  short target, faint text, ringless focus, running animation) and requires each to be caught.

## Coverage notes

- **200% zoom** is `e2e/navigation.spec.ts`'s zoom test: a 720 CSS-px viewport (a 1440 window at
  200%) with root `zoom: 2`, a 360px layout budget that is strictly harder than real zoom, walked
  over every primary route. The 320 column here is WCAG reflow's 320 CSS px.
- **Token contrast** stays `e2e/polish.spec.ts`'s token-pair and wash-composite matrix; the
  rendered sampler below measures real pages on top of it. Text inside SVG (chart ticks, whose
  pairs polish.spec measures by token) and text over images or partial opacity is skipped and
  counted, never guessed — the 22 skips on the dashboard are the chart.
- **Long names and unbroken log lines**: `inbox/long-content` (unbroken title and repository on
  the first rows) and `task-detail/long-content` (unbroken command, repository, author, summary,
  branch, gate name and a 2,000-character log line).
- **The mobile drawer's** focus containment and return are `e2e/navigation.spec.ts`'s drawer
  tests at 768/390/360; the four other dialogs are covered below.
- Not covered: an unreachable-but-tabbable control has no negative control (the reach diff has
  nothing to plant that a real page would not also reach), and dialog containment has none.
